Mechanism walkthrough

Same scenario, three topologies

A seeded marketing agent runs brief → research → plan → create → review, where review scores draft one at 0.42 against a 0.80 bar. What happens next depends on nothing but the shape of the edges. This page maps each lab feature to what it proves.

Honest limits. Timings are deterministic fixtures, not wall-clock measurements; the simulated interrupt() is a pause flag, not durable storage. The topology lesson is real.

Start here

What this lab proves

Pick graph and press Run to end: review fails at 0.42, the vermilion back-edge fires, attempt 2 drafts with research and plan intact, passes at 0.91, and interrupt() freezes the run for approval. Now run chain — same brief, same draft, dead end. Then while: watch the state tape blank on every restart while the ledger keeps the receipts — 18.6 s burned and still off brand, where the graph spends 10.1 s and ships.

The mechanisms

Features and what each proves

Feature 01

The rail

Seven stations — brief research plan create review approve publish — drawn as a transit line. Every forward edge points right; the dotted vermilion arc curving back from review to create is the only edge a chain cannot draw.

Proves
topology is the feature — the nodes never change.
Key detail
in chain mode the arc renders as a severed stub.
Feature 02

Mode: chain

A DAG executor. review exits with no outgoing route for failure, so the run dead-ends holding the 0.42 draft — research and plan produced, then stranded.

Proves
a chain physically cannot express "try again".
Key detail
5 spans, 6.2 s spent, status dead-ended.
Feature 03

Mode: while

The naive patch — while (!onBrand) rerun(). Each restart re-invokes the whole chain cold, so attempts resets to 1 and the same 0.42 draft comes back. Emits a state-lost event per restart.

Proves
retries without memory burn budget and still fail.
Key detail
3 cycles × 6.2 s = 18.6 s; ledger shows research re-fetched 3×.
Feature 04

Mode: graph

Checkpointed cyclic execution. The review → create back-edge carries accumulated state into the retry; attempt 2 scores 0.91 and the run continues to approve.

Proves
the graph's shape IS the retry policy.
Key detail
10.1 s total, 3.1 s retry cost, status completed.
Feature 05

The state tape

A checkpoint strip under the rail — attempts · research · plan · draft · score · ms. In graph mode the cells stay lit through the retry; in while mode they visibly blank on every restart.

Proves
what a checkpoint is: state that survives going back.
Key detail
wiped cells are the argument — watch them in while mode.
Feature 06

The trace ledger

A LangSmith-style span table — one row per node execution, appended never overwritten. Vermilion rows mark the retry: create@2 and review@2, 3.1 s of the 10.1 s total.

Proves
observability answers "what did the retry cost?"
Key detail
the ledger is framework-agnostic — it logs all three modes.
Feature 07

interrupt() → Approve

On a passed review the graph doesn't publish — it freezes at approve with state checkpointed. The Approve button calls resumeRun and the run picks up exactly where it left off.

Proves
a human-in-the-loop pause is one line, not an architecture.
Key detail
status moves awaiting-approval → completed.
Feature 08

/api/run

The server drives the same lab.mjs the browser imports — GET /api/run?mode=graph returns the full ledger, totals, and resting status as JSON.

Proves
one deterministic model, three drivers: UI, CLI, API.
Key detail
try ?mode=chain and ?mode=while.

Limits

What this demo does not claim

  • Timings are deterministic fixtures that mirror the article's numbers, not measurements of real LLM latency.
  • Real model output is stochastic — attempt 1 always scoring 0.42 is the seeded failure, not a claim about chains.
  • The simulated interrupt() is a pause flag in memory; real durable execution persists checkpoints across restarts.
  • The ledger mimics a trace view; it is not an observability platform, and it lives in this demo only.
  • A passing run means "this topology can go back" — never "the agent is correct".
